# 常见问题

## 部署相关

### 服务器需要什么配置？

| 人数 | 配置 | 备注 |
|------|------|------|
| 10 人内 | 1 核 1G | 可以运行，余量有限 |
| 几十人 | 2 核 4G | 推荐起点 |
| 上百人 | 4 核 8G+ | LiveKit 建议部署在独立服务器 |

资源消耗主要来自音频转发和带宽，而非 CPU。每个发言者约占用 40-60 kbps 上行带宽，收听侧按人数累加。

### 是否必须使用 Docker？

并非必须。系统支持以单个二进制文件运行，前端资源已打包在内；但该方式需要自行另外部署 LiveKit。详见 [单二进制部署](/deploy/binary)。

### 没有域名时能否使用？

可以使用，但语音功能不可用。浏览器仅在 HTTPS 或 localhost 环境下授予麦克风权限。

内网测试可以使用 `http://localhost`，或采用自签名证书；对外提供服务必须使用正规 CA 签发的证书。

### 需要开放哪些端口？

最少需要开放以下四个：

- `80/tcp` + `443/tcp` 用于网页访问（Caddy 或自行部署的反向代理）
- `7882/udp` 媒体主通道
- `7882/tcp` 媒体兜底
- `3478/udp` TURN

媒体端口未开放时语音无法正常工作。**7880 / 7881 不需要对公网开放**：7880 只绑宿主机回环供本机调试，LiveKit 信令对外走应用内置的同源反向代理 `/livekit`。云服务器上需要在系统防火墙和云厂商安全组中同时放行。

### 能否部署到群晖 NAS？

可以，使用 Docker 部署。ARM 机型拉取 `linux/arm64` 镜像。NAS 的 CPU 性能较弱，人数较多时可能出现卡顿。

### 是否支持 ARM？

支持。发布镜像提供 `linux/amd64` 和 `linux/arm64`，二进制文件也提供 arm64 和 armv7 版本。

## 使用相关

### 用户数是否存在上限？

软件层面没有硬性限制，实际上限取决于以下因素：

- 数据库：SQLite 约 50 人以内同时在线较为稳定
- 带宽：实际的主要瓶颈
- LiveKit 所在服务器性能

### 能否同时进入多个语音频道？

不支持。同一用户同一时间只能位于一个语音频道，切换频道时会自动退出上一个频道。

### 关闭浏览器后语音会断开吗？

会断开。浏览器方案下关闭标签页即断开连接。

需要保持常驻连接时使用[桌面客户端](/guide/desktop)——关闭窗口只是隐藏到托盘，语音连接保持不断。

### 是否支持视频？

数据模型中包含 `audioOnly` 字段，默认仅启用音频。当前版本主要面向游戏语音场景，视频并非重点方向。

### 消息能否编辑和删除？

支持。用户可以随时编辑和删除自己的消息；删除他人消息需要 `message:delete_others` 权限。

### 是否支持私聊？

支持。左侧栏「聊天」面板即为私聊会话。

### 数据存储在哪里？

- 用户、消息、房间 → 数据库（SQLite 文件或 PostgreSQL）
- 头像、附件 → 所配置的存储（本机目录或对象存储）
- 语音 → 不存储，实时转发

除使用 LiveKit Cloud 外，不会有任何数据发送到第三方。

## 语音相关

### 听不到声音问题排查

按以下顺序排查：

1. 浏览器是否已授予麦克风权限
2. 服务器是否已放行 `7882/tcp`、`7882/udp`、`3478/udp`
3. 页面使用 HTTPS 时，`/api/v1/signal/token` 返回的 `serverUrl` 是否为 `wss://<你的域名>/livekit`
4. LiveKit 容器是否正常运行：`docker compose ps livekit`

详细步骤见[故障排查](/deploy/troubleshooting)。

### 回声问题排查

外放状态下扬声器声音会被麦克风拾取形成回声，佩戴耳机可以避免。

### 声音断续问题排查

带宽不足或 UDP 丢包所致。检查服务器出网带宽是否已达到上限。

### 能否调节单个成员的音量？

支持。在成员列表中点击对应成员，弹出卡片中包含音量条，音量按成员独立调节。

### 「静音」与「禁言」的差异

- **静音**：仅影响本地听到的声音，其他成员不受影响
- **禁言**：服务端强制执行，被禁言的成员无法发送声音，但仍可以收听

## 配置相关

### LiveKit 是否需要 Redis？

不需要。单节点 LiveKit 不依赖 Redis，多节点集群才需要，该场景需自行按 LiveKit 文档配置，不在 GOSpeak 的部署清单范围内。

### 是否需要外部 NATS 服务？

不需要，也无法配置。NATS 为进程内嵌运行，负责内部事件、JWT 黑名单、密钥轮换、异步任务。

### 如何修改端口？

```ini
SERVER_PORT=9000
```

Docker 部署还需要修改 compose 中的端口映射。

### 配置修改后不生效的排查

Docker 部署需要使用 `docker compose up -d`，不能使用 `restart`——后者不会重新读取环境变量。

后台修改过的配置（SFU、存储、邮件、OAuth）保存在数据库中，优先级高于环境变量。

### 能否修改界面文字？

前端代码位于 `app/web`，修改后重新构建。系统未内置多语言切换。

## 账号相关

### 默认管理员账号是什么？

`admin` / `admin123`。首次启动时若数据库中不存在 `admin` 账号则自动创建。**对外网开放前必须修改默认密码。**

### 管理员密码找回方法

直接修改数据库中的密码记录，或者删除数据后重新初始化（会丢失数据）。

### 如何封禁用户？

将用户角色改为 `ban` 后，中间件会拦截该用户的全部受保护接口请求。

### 访客和注册用户的差异

访客无需注册，通过邀请码进入，可用功能由域的三个开关决定。访客有独立的封禁列表。

## 升级相关

### 如何升级？

```bash
git pull
cd deploy
docker compose up -d --build
```

数据库表结构自动迁移，升级前应先备份。

### 升级是否会丢失数据？

不会。数据保存在数据卷中，重建容器不影响数据。

但执行 `docker compose down -v` 时，`-v` 会删除数据卷——该操作不可逆。

### 能否从旧版本直接升级到最新版？

跨多个版本升级时建议先备份再执行，中途可能存在不兼容的迁移；单个版本之间一般没有问题。
