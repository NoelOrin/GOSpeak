# Room List 与域详情主体 UI 优化设计

日期：2026-08-02

## 目标

优化两处前端界面，不改变业务接口、权限规则或核心交互：

1. 房间列表项在侧栏窄宽度下保持稳定布局，长名称单行省略，悬停时展示完整名称。
2. `/manage/domains/$domainUUID` 域详情主体参考 `/manage/mute` 的管理页视觉规范，重排为清晰的设置/成员双栏布局。

管理域左侧导航和全局顶部导航不在本次范围内。

## 现状与约束

- 房间项位于 `app/web/src/components/room/roomList.tsx` 的 `RoomItem`。
- 现有房间项使用 daisyUI `tooltip`，当前 Tooltip 文案为进入/密码提示，不能同时稳定承载长名称。
- 域详情页已有表单、成员加载、成员移除、权限判断、错误处理和确认弹窗，必须保留。
- 管理页公共组件为 `ManagePage`、`ManageHeader`、`ManageSection`；`/manage/mute` 使用这些组件形成统一卡片和表格样式。
- 当前工作区中的域详情路由是未跟踪新增文件，修改时保留其已有功能代码与数据流。

## 设计

### 1. RoomList 项

房间按钮使用可收缩的 flex 结构：

- 外层按钮继续占满列表宽度，并设置 `min-w-0`。
- 左侧图标、名称和密码图标放入 `min-w-0 flex-1` 容器。
- 名称使用 `min-w-0 flex-1 truncate whitespace-nowrap`，保证长名称不挤压右侧人数。
- 人数区域使用 `shrink-0`，固定显示 `count/limit`。
- Tooltip 展示完整名称；密码房间在名称后追加密码提示，不覆盖完整名称。
- Tooltip 仅承担查看信息，不改变点击、双击、移动端加入逻辑。

### 2. 域详情主体

页面外层改用管理页公共结构：

- `ManagePage` 负责统一内边距、纵向间距和滚动。
- `ManageHeader` 显示返回按钮、域名、描述；返回行为和当前路由保持不变。
- 主体使用响应式双栏：桌面端左侧固定约 `400px` 设置卡片，右侧成员管理卡片占据剩余宽度；窄屏切换为上下排列。
- 设置和成员分别使用 `ManageSection`，沿用 `/manage/mute` 的标题、描述、边框、表头和空状态风格。
- 成员卡片使用 `padded={false}`，让表格贴合卡片内容区；保留横向溢出处理。
- 设置表单保留域名称、描述、房间上限、公开域和保存按钮；只调整字段间距、标签层级、按钮对齐和错误提示。
- 无管理权限时保留只读展示，沿用同一张设置卡片，不显示可编辑控件。
- 成员刷新入口放在成员卡片标题右侧；成员加载、错误、空列表、移除确认和成功/失败 Toast 保持现有语义。
- 长描述、长用户名和长域名都限制在各自容器内，避免撑破双栏；表格列允许横向滚动。

目标结构：

```text
ManagePage
├── ManageHeader
└── responsive grid
    ├── ManageSection: 域设置
    └── ManageSection: 成员管理
```

### 响应式行为

- `lg` 及以上：设置列固定宽度，成员列自适应。
- `lg` 以下：两张卡片上下排列，设置卡片先出现。
- 页面主体保持外层滚动；不引入独立嵌套滚动容器，避免移动端滚动冲突。

## 不改动内容

- 不新增 API、模型、权限码或路由。
- 不改变域设置校验规则、保存请求、成员加载和移除请求。
- 不改左侧管理导航、顶部导航和其他管理页面。
- 不改变房间项选择、加入、密码弹窗和成员点击行为。

## 验证

1. 运行前端类型检查或构建，确认 SolidJS/TypeScript 类型正确。
2. 启动前端预览，检查域详情桌面双栏和窄屏上下布局。
3. 在 RoomList 中验证长名称省略、悬停 Tooltip、人数显示和房间加入逻辑。
4. 验证成员表格加载、空状态、刷新和移除确认仍可用。
5. 检查浏览器控制台无新增错误。
