# 全局 UI Review — 风格统一 / 圆角梯度 / 图标和谐

- 日期：2026-11-08
- 范围：`app/web/src`（不含 `_solid-legacy`）+ `packages/components/src`
- 基线：`app/web/visual-baseline/baseline/*.png`（light/dark 各 17 页）
- 方法：token 定义对照 + 全量 className 统计 + 基线截图目视 + 真实 Tailwind v4 编译验证

> **实施状态（2026-11-08 同日完成）**：本报告的 P0 + 主要 P1 已落地，详见文末「7. 实施记录」。
> 其中 §3.2 关于 `strokeWidth` 的判断有误（当时 grep 漏统计），已在 §3.2 就地更正。

---

## 0. 结论摘要

设计 token 层（`theme.css`）本身是合格的：圆角档位、语义别名、明暗色都定义得清楚。**问题全部出在 token 与代码之间**——规范只写在注释里，没有落到组件 API 上，于是每个页面自己实现了一遍"卡片 / 按钮 / 图标尺寸"。

三个核心问题：

| # | 问题 | 量化 |
|---|---|---|
| P0-1 | **"卡片"有三种半径**：Card 组件 8px、ManageSection 16px、列表行 12px | 同层级元素 3 套值 |
| P0-2 | **控件尺寸不成体系**：输入框 h-10、主按钮 h-9、Button 组件默认 h-12 | 7 档控件高度并存 |
| P0-3 | **图标尺寸 15 档**，14/15/16 三个只差 1–2px 的尺寸混用，strokeWidth 全局为 0 处覆盖 | 15 档 / 0 处 |

此外还有两个结构性欠债：**双轨语义层**（`ds-*` 109 个文件 vs Tailwind token）和 **组件复用率过低**（手写 `<button>` 158 处 vs `<Button>` 36 处）。

## 1. 圆角梯度

### 1.1 现状：token 定义 vs 实际使用

`packages/components/src/theme.css:69-109` 定义的档位（已用 Tailwind v4.3.1 实际编译验证，全部正确生成）：

| 档位 | 实际值 | 文档约定用途 |
|---|---|---|
| `rounded-xs` | 2px | 缩略图、分隔条 |
| `rounded-sm` | 4px | 输入框、小按钮、徽章 |
| `rounded-md` | 6px | 列表行、内嵌小面板 |
| `rounded-lg` | 8px | **默认：按钮、卡片、下拉面板** |
| `rounded-xl` | 12px | 管理页 section、设置面板 |
| `rounded-2xl` | 16px | 弹窗、页面级浮层 |
| `rounded-3xl` | 24px | 极少使用 |
| `rounded-full` | 9999px | 头像、状态点、标签 |

实际用量：

```
rounded-sm  129   rounded-full  76   rounded-lg  44   rounded-xl  24
rounded-2xl  18   rounded(裸)   17   rounded-md   9   rounded-t-lg 2
rounded-b-lg 1    rounded-none  1    rounded-[var(--radius-field)] 1
```

关键发现：**语义别名 `rounded-field / rounded-card / rounded-panel / rounded-overlay / rounded-pill` 使用次数为 0**。规范里写了"按用途选型时优先用它"，代码里一次都没用——规范与实现完全脱节。

### 1.2 P0-1 同一层级的"卡片"有三种半径

| 位置 | 类名 | 值 |
|---|---|---|
| `packages/components/src/components/card.tsx:11` | `rounded-lg` | 8px |
| `app/web/src/components/manage/ManageShell.tsx`（ManageSection） | `rounded-2xl` | 16px |
| `app/web/src/components/manage/ManageShell.tsx`（ManageNotice） | `rounded-2xl` | 16px |
| `app/web/src/components/discover/DiscoverMyDomains.tsx:59` | `rounded-xl` | 12px |

管理页用 16px 大圆角、其他地方用 8px 小圆角，导致"设置页"和"房间页"看起来像两个产品。基线截图里很明显：`manage-index-light.png` 的白卡片是 16px，`home-light.png` 的卡片是 8px。

### 1.3 P0 文档与组件实现不一致（3 处）

| 元素 | 文档要求 | 实际实现 | 文件 |
|---|---|---|---|
| Dialog 弹窗 | `2xl` = 16px | `lg` = 8px | `dialog.tsx:21` |
| Button | `lg` = 8px | `sm` = 4px | `button.tsx:8` |
| Select 下拉面板 | `lg` = 8px | `sm` = 4px | `select.tsx:64` |

其中 Button 的 4px 其实是**更好的选择**（与 Input 的 4px 对齐），真正要改的是文档；但 Dialog 8px 配 `shadow-lg`，在 16px 卡片背景上显得"方"，是明确的视觉缺陷。

### 1.4 P1-1 浮层半径四套值

同样是 `position: fixed` 的浮层：

- `roomItem.tsx:297` `rounded-lg` + `shadow-xl`
- `userInfoPopover.tsx:58` `rounded-xl` + `shadow-xl`
- `roomDetail.tsx:242` `rounded-lg` + `shadow-xl`
- `messageInput.tsx:189` `rounded-lg` + `shadow-xl`
- `userCard.tsx:76` `rounded-xl` + `shadow-xl`

对话框额外还有 `rounded-lg`（dialog）和 `rounded-2xl` 混用。

### 1.5 P1-2 同心圆规则缺失

`ManageSection` 是 16px 圆角 + 16/20px padding，内部又放 8px 圆角的行块。按同心圆公式（内半径 = 外半径 − padding）应为 0–4px，实际 8px，视觉上内块"过圆"、与外框不平行。

`manage-sfu-light.png` 里"LiveKit 强制能力对比"卡片（16px）内嵌 6 个能力小卡（8px，padding 12px）最典型：内卡看起来比外卡还圆。

### 1.6 P2 残留写法

- `rounded`（裸，17 处）：Tailwind v4 编译结果 = `var(--radius)` = **8px**，等价于 `rounded-lg`，但读代码的人无法判断意图。集中在 `roomList.tsx:33,36`、`VoiceStatusBar.tsx:88,107,136`、`roomDetail.tsx:149,229,276`、`MessageInput.tsx:270,281`、`channelHeader.tsx:60,70` 等。
- `rounded-none` 1 处、`rounded-t-lg` / `rounded-b-lg` 3 处（表头与卡片组合时手动抹圆角）。
- `rounded-[var(--radius-field)]` 1 处：`AvatarCropperModal.tsx:118`，唯一一处任意值写法。

### 1.7 P1-3 控件高度 7 档并存

```
h-9  57 次   ← 事实标准
h-7  19 次
h-10 15 次   （Input / Select 固化高度）
h-11 15 次
h-8  14 次
h-6   5 次
h-12  2 次   （Button 组件默认高度！）
```

最直接的症状：**表单行里输入框 40px、按钮 36px，底边不齐**。而 `Button` 组件默认 `h-12`（48px），与全站 36px 的实际尺度差一档，所以 158 个手写 `<button>` 里有 24 处重复抄了同一串类名：

```
border-border bg-card text-foreground hover:bg-muted inline-flex h-9
cursor-pointer items-center gap-2 rounded-sm border px-3 text-sm shadow-none
```

出现在 **16 个文件 24 处**（`manage/users`、`manage/oauth`、`manage/mute`、`manage/storage`、`link.tsx`…）。这就是"缺少 `Button variant="outline" size="sm"`"的证据。

### 1.8 P2 胶囊按钮孤例

`MuteDurationPicker.tsx:158` 是唯一一个 `rounded-full` + `h-11` 的按钮，其余按钮全是 4px/36px 直角块。一行胶囊在整页方块里非常突兀。

## 2. 风格统一

### 2.1 P0 双轨语义层（最影响观感的结构问题）—— 已在 §8 解决

`app/web/src/assets/styles/discord-surface.css` 定义了一整套 `--ds-*` 变量和工具类，它们**全部映射到现有 token**（设计初衷是好的），但结果是同一语义有两套写法：

| 语义 | Tailwind 写法 | ds-* 写法 | 用量 |
|---|---|---|---|
| 主文字 | `text-foreground` | `ds-text` / `ds-body` | 22+17+15 |
| 次要文字 | `text-muted-foreground` | `ds-muted` / `ds-faint` | 22+7 |
| 卡片底 | `bg-card` | `ds-panel` | 79 vs 5 |
| 边框 | `border-border` | `ds-border` | 15 |
| hover 底 | `hover:bg-muted` | `ds-hover` | 5 |

`ds-*` 覆盖 **109 个文件**。同一份代码里 `ds-panel ds-border` 和 `bg-card border-border` 并存，后续任何主题调整都要改两处，且新同学无法判断该用哪套。

### 2.2 P1 次要文字有 11 档透明度 —— 已在 §9 解决

```
text-foreground/50  74    /40  36    /60  36    /70  39    /55  13
text-foreground/75  12    /80  10    /45   9    /65   3    /30   2    /20  1
```

而语义 token `text-muted-foreground` 只用了 **12 次**。

同一层级的说明文字，在 A 页面是 `/50`、B 页面是 `/45`、C 页面是 `/55`，肉眼看不出但整体会显得"灰得没规律"。这是全站最普遍的细节失分点，`manage-sfu-light.png` 里副标题、卡片说明、脚注三种灰度就是三档不同透明度。

### 2.3 P1 任意字号 5 档

```
text-sm     210      text-xs  171
text-[14px]  28  ← 与 text-sm 完全相同，应直接替换
text-[11px]  23  ← 介于 xs(12) 与 10 之间的野生档位
text-[10px]  17
text-[12px]   5  ← 与 text-xs 完全相同
text-[13px]   2
text-[15px]   3
```

`text-[14px]` 的 28 处集中在表单 label（`form/index.tsx:176`、`profileForm.tsx:238`、`shared.tsx:63`…），属于可以机械替换的批次。

### 2.4 P2 阴影 5 档

`shadow-sm` 30 / `shadow-xl` 10 / `shadow-none` 9 / `shadow-md` 4 / `shadow-lg` 4。

`shadow-none` 全部是为了"抵消 Button 默认阴影"而写的补丁（见 1.7）。`shadow-md`（4 处）与 `shadow-lg`（4 处）语义重叠，且用在 Dialog/Toast 上，与 `shadow-xl` 的浮层并存。

### 2.5 P2 品牌色的明暗漂移

`theme.css` 里 `--accent` 亮色是 lime（`oklch(92.78% 0.264 122.962)`）、暗色是 teal（`oklch(77% 0.152 181.912)`）——**同一批侧栏图标方块在明暗主题下从黄绿变青**（对比 `home-light.png` 与 `discover-dark.png`）。`--secondary` 同理是亮橙 / 暗洋红。

如果这是刻意为之（暗色下 lime 会刺眼）就应写进规范；否则建议收敛到同一色相，只调亮度/彩度。目视判断：暗色下的 teal 与 indigo 主色关系更协调，亮色下的 lime 与 magenta 搜索按钮同时高饱和，是全站"最吵"的两个色块。

### 2.6 P1 组件复用率过低

| 元素 | 手写 | 组件 |
|---|---|---|
| 按钮 | `<button>` 158 | `<Button>` 36 |
| 输入框 | `<input>` 56 | `<Input>` 22 |

组件库只有 11 个组件，且 `Button` 的尺寸/变体不覆盖实际需求（缺 `outline + sm + 无阴影`、缺 `h-9`），于是大家绕过它。**圆角和高度之所以收敛不了，根因在这里**。

## 3. 图标和谐

### 3.1 P0 15 档尺寸

`lucide-react` 图标（62 个文件引入），`size={N}` 分布：

```
16 → 54    14 → 43    15 → 21    18 → 15    20 → 13    12 → 9
13 →  4    32 →  3    11 →  2    10/19/22/26/28/30 各 1
```

问题不在"档位多"，而在 **14 / 15 / 16 三档混用（合计 118 次）**——相差 1px 无法形成清晰层级，只会让人感觉"图标大小不齐"。

同一个图标在不同位置尺寸不同：

| 图标 | 尺寸集合 |
|---|---|
| `X` | 12 ×2, 14 ×2, 15 ×1, 16 ×4 |
| `Check` | 10 ×1, 14 ×2, 15 ×1 |
| `Search` | 14 ×3, 15 ×1 |
| `Plus` | 13 ×1, 14 ×1, 16 ×3, 20 ×1 |
| `Hash` | 15 ×2, 16 ×5, 26 ×1, 32 ×1 |
| `Headphones` | 14 ×2, 20 ×1, 30 ×1 |

`size={15}` 的 21 处散布在 `discover`、`link.tsx`、`domain.$domainUUID.tsx`、`manage/*` 等 12 个文件，像是某次全局替换的残留。

### 3.2 P1 strokeWidth 值混乱（已更正）

初版写的是"全仓库 `strokeWidth` 出现 0 次"，这是 grep 漏统计导致的错误。实际情况是 **13 处、5 个不同值**：

```
2.1 → 5 处（侧栏 20px 图标，含一个 iconProps 默认值）
1.5 → 3 处（32px 插图式图标）
2.4 → 2 处（channelHeader、MessageInput 的 20px 图标）
2.5 → 2 处（roomItem 的 16px 图标）
1.6 → 1 处（domainWorkspace 的 30px 图标）
2   → 1 处（TextRoomPanel 26px）
```

关键认知修正：lucide 的 SVG 是 `viewBox="0 0 24 24"`，`width/height` 缩放时**描边会等比缩放**，所以"小图标描边偏粗"这个判断不成立。真正的问题是有人为了追求"看起来更实"在个别图标上手调 2.4 / 2.5，导致**同一排图标粗细不一致**（`roomItem` 的 Hash/Mic 就比旁边的图标明显粗一圈）。

处理方式：删掉 2.1 / 2.4 / 2.5（回到默认 2），`1.6 → 1.5`，最终只保留两条规则——**UI 图标用默认 2，32px 插图式图标用 1.5**。


### 3.3 P1 缺图标封装

没有任何 `<Icon>` 组件或尺寸常量，全靠调用方手写 `size={14}`。对比：颜色有 token、圆角有 token，**图标尺寸没有 token**——这是图标的尺寸无法收敛的制度性原因。

### 3.4 P2 图标形态混排

`ProviderIcon.tsx` 里 5 个 OAuth 品牌图标是**多色填充**（Google 四色、QQ 蓝、Discord 靛、Microsoft 四色），与全站 lucide 单色线性图标在登录页并排（`login.tsx`），视觉重量明显不齐。这属于品牌资产很难统一，但可以通过**统一承载容器**（同尺寸圆形/方形底 + 同内边距）来平衡。

## 4. 建议规范（可直接落地）

### 4.1 圆角梯度（保留 `--radius: 8px`）

| 层级 | token | 值 | 用途 | 现状需改 |
|---|---|---|---|---|
| L0 | `xs` | 2px | 分隔条、缩略图 | — |
| L1 | `sm` | 4px | **所有表单控件与按钮** | 保持（Button/Input 已是 4px） |
| L2 | `md` | 6px | 列表行、行内小块、嵌套块 | 从 8px 降下来 |
| L3 | `lg` | 8px | **卡片、行内面板、下拉面板、浮层** | Card 保持；Select 4→8；浮层统一到 8 |
| L4 | `xl` | 12px | **页面 section** | ManageSection 16→12 |
| L5 | `2xl` | 16px | **仅 modal** | Dialog 8→16 |
| L6 | `full` | 胶囊 | 头像、状态点、Tag、圆形按钮 | 按钮禁止使用 |

**同心圆规则**（必须写进 lint 检查项）：

```
内层半径 = 外层半径 − 内边距，且至少低一档
例：12px section + 16px padding → 内层 ≤ 4px（不能是 8px）
```

配套动作：
1. 删掉未使用的语义别名，或反过来——把 `rounded-card / -panel / -overlay` 定为**唯一合法写法**，其余档位禁止直接使用（依赖 biome 自定义规则或 code review 兜底）。
2. 消灭 17 处裸 `rounded`（全部→`rounded-lg`）、3 处 `rounded-t/b-lg`、1 处任意值。

### 4.2 控件尺度

| 尺寸 | 高度 | 用途 |
|---|---|---|
| xs | 28px (h-7) | 表格行内操作 |
| sm | 32px (h-8) | 工具栏、图标按钮 |
| **md（默认）** | **36px (h-9)** | **主按钮、表单行、页面操作** |
| lg | 44px (h-11) | 登录/注册等强场景 |

- `Button` 默认 `h-12` → **改为 `h-9`**，并补 `outline + sm + shadow-none` 变体，回收那 24 处重复类名。
- `Input` / `Select` 由 `h-10` → **`h-9`**，与按钮齐平。
- `h-6 / h-10 / h-11` 的非表单用法逐项归位到上表。

### 4.3 文字层级（11 档 → 4 档）

| 语义 | 建议写法 | 替代现有 |
|---|---|---|
| 主文字 | `text-foreground` | /100, /80, /75 |
| 次要文字 | `text-foreground/70` | /70, /65, /60, /55 |
| 弱文字 | `text-foreground/50` | /50, /45, /40 |
| 极弱/占位 | `text-foreground/35` | /30, /20 |

字号：只保留 `text-xs(12) / text-sm(14) / text-base(16) / text-lg(18) / text-xl(20)`。
`text-[14px]→text-sm`、`text-[12px]→text-xs` 可机械替换（33 处）；`text-[10px]/[11px]` 统一到 `text-xs` 或 `text-[10px]` 二选一（建议合并到 `text-xs`，除徽章外）。

### 4.4 图标规范

**尺寸只留 5 档**，并吸附：

| 语义 | 尺寸 | 用途 | 迁移映射 |
|---|---|---|---|
| `xs` | 12 | 徽章内、极小提示 | 10, 11 → 12 |
| `sm` | 14 | 密集行内、表格操作 | 13 → 14；15 → 14 |
| **`md`（默认）** | **16** | 按钮内、菜单、导航 | — |
| `lg` | 20 | 页头、工具栏主操作 | 18, 19, 22 → 20 |
| `xl` | 24 | 空状态 | 26, 28 → 24 |
| `hero` | 32 | 插画式 | 30 → 32 |

**strokeWidth**：`12/14 → 1.75`，`16/20/24 → 1.75`，`32 → 1.5`（统一 1.75 即可，视觉最接近现在的 2 但更细腻）。

**封装**：新增

```tsx
// packages/components/src/components/icon.tsx
export const iconSize = { xs: 12, sm: 14, md: 16, lg: 20, xl: 24, hero: 32 } as const;
export function Icon({ as: C, size = "md", ...rest }) {
  return <C size={iconSize[size]} strokeWidth={1.75} {...rest} />;
}
```

之后禁止裸写 `size={数字}`（可加 biome `noRestrictedSyntax` / 自定义 grep CI 门禁）。

### 4.5 收敛 `ds-*` 双轨

分三步，低风险：

1. **冻结**：新代码不再引 `ds-*`。
2. **映射表机械替换**（109 文件，纯字符串替换，可脚本化）：

| 旧 | 新 |
|---|---|
| `ds-text` / `ds-body` | `text-foreground` |
| `ds-muted` / `ds-faint` | `text-foreground/70` |
| `ds-panel` / `ds-bg` | `bg-card` |
| `ds-subtle` / `ds-hover` | `bg-muted` |
| `ds-border` | `border-border` |
| `ds-blurple` | `bg-primary` |
| `ds-icon-btn` | 保留为组件（`.ds-icon-btn` 32px + 4px 是合理的） |

3. 保留 `ds-surface`（作用域容器）与 `ds-scroll`、`ds-markdown`（Markdown 作用域），这三个不是语义色重复，而是真实需要的。

## 8. 第二轮实施：`ds-*` 双轨语义层合并（§2.1 已解决）

### 8.1 做法

`discord-surface.css` 里的 `--ds-*` 变量本质是 token 的同义重命名，所以按"变量 → token 工具类"逐 token 替换，而不是引入新色值：

| 原（`ds-*`） | 现（Tailwind token） | 替换数 |
|---|---|---|
| `ds-text` / `ds-body` | `text-foreground` | 32 |
| `ds-muted` / `ds-faint` | `text-muted-foreground` | 29 |
| `ds-panel` / `ds-bg` / `ds-userbar` | `bg-card` | 12 |
| `ds-subtle` / `ds-input-bg` | `bg-muted` | 6 |
| `ds-hover` / `ds-msg-row` | `hover:bg-muted` | 6 |
| `ds-border` | `border-border` | 15 |
| `ds-divider` | `bg-border` | 1 |
| `ds-blurple` | `bg-primary` | 4 |
| `ds-danger` | `hover:text-destructive` | 2 |
| `ds-deep` | `bg-sunken`（新增 token） | 7 |
| `ds-active` | `bg-selected`（新增 token） | 2 |
| `bg-[var(--ds-xxx)]` 任意值 | 对应 token 工具类 | 18 |

新增两个真正缺失的语义色（`theme.css` 的 `@theme inline`）：

```css
--color-sunken:   color-mix(in oklab, var(--muted) 72%, var(--foreground) 10%);  /* 语音区/覆盖层底 */
--color-selected: color-mix(in oklab, var(--muted) 74%, var(--foreground) 9%);   /* 选中态底 */
```

### 8.2 保留的 4 个类（Tailwind 表达不了）

`discord-surface.css` → 重命名为 `workspace-surface.css`，只留：

| 类 | 用途 | 用量 |
|---|---|---|
| `.ds-surface` | 作用域容器（`::selection`、`.ds-markdown` 后代规则挂靠点） | 1 |
| `.ds-icon-btn` | 32px 工作区图标按钮 + `[data-active]` 态 | 6 |
| `.ds-scroll` | 细滚动条 | 2 |
| `.ds-markdown` | Markdown 正文局部排版 | 1 |

`--ds-*` 变量块整段删除，文件内改为直接引用 `--foreground / --card / --muted / --border / --primary / --radius-*`。

### 10.5 顺带发现
